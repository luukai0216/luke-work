## 决策记录

### DD-001：全站首次加载 Loading 方案

- **日期**：2026-03-30
- **决策人**：luke
- **背景**：用户首次访问（清空缓存）时，浏览器需下载 React、ECharts 等 JS 文件，期间页面呈纯黑背景。实测 WiFi 下约 1~2 秒，Slow 3G 下可达 8~15 秒，体验较差。
- **选项**：
  - A：品牌 Logo + 脉冲动效 — 优势：品牌感强、开发成本低（约 0.5 天）、纯 CSS 无框架依赖 / 劣势：视觉效果一般（★★★★☆），无页面结构预示
  - B：顶部进度条 — 优势：开发成本极低（约 2 小时）、实现最简单 / 劣势：品牌感弱（★★★☆☆），视觉效果最差
  - C：品牌加载壳 + 真实布局骨架 — 页面进入后先出现品牌底色/渐变背景，Logo 先行建立品牌识别，同步渲染导航骨架、Hero 标题骨架、CTA 按钮骨架、关键数据卡骨架；整体节奏控制在 300~500ms；真实内容就绪后原位替换。优势：视觉效果最佳（★★★★★）、骨架贴近真实布局避免加载后版式重排、品牌感强、shimmer 淡入纯 CSS 实现 / 劣势：开发成本稍高，骨架需随页面布局变化同步维护
- **决策**：选择 C（品牌加载壳 + 真实布局骨架）
- **理由**：首屏体验的核心目标是"可信赖感"，不是动效炫技。骨架贴近真实布局，用户能感知页面结构已就绪、系统正在工作，不会面对无反馈的空白等待；不允许空 root 直接等待是设计红线；轻量淡入 + shimmer 优先于重品牌开场动画，符合竞品第一梯队（Morpho、Uniswap、Spark）的主流做法。
