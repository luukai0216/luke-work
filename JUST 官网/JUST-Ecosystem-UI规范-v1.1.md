# JUST Ecosystem UI 规范 v1.1

整理日期：2026-09-21。面向 luke 的 UI 设计工作；本阶段为规范与组件准备，不是完整页面定稿。

## 1. 依据与优先级

1. **当前官网优先**：[JUST 首页](https://just.network/) 与 [JustEcosystem](https://just.network/foundation)。本次检查了页面呈现与浏览器计算样式。
2. **原始设计稿补充**：[参考页](https://www.figma.com/design/LmMqOnKRrHm6afgvdI4yx2/JUST-luke?node-id=0-1)，包括 `V2改动内容`（2:58）、`08.12`（2:1873）、已有规范（2:921）、已有组件（2:1013）。
3. **页面内容参考**：[Ecosystem 需求理解](./Ecosystem-需求理解.md) 与本地原型。它们说明业务结构，不能覆盖官网品牌样式。
4. **新增设计建议**：原稿和官网没有明确覆盖的交互、响应式、组件属性，均标为“建议”。

目标 [Ecosystem 页面](https://www.figma.com/design/LmMqOnKRrHm6afgvdI4yx2/JUST-luke?node-id=2-5597) 在本次检查时为空。

## 2. 页面定位与视觉方向

面向开发者、项目与合作方、社区贡献者，帮助他们找到合作、支持与治理入口。

视觉关键词：**开放、清晰、可信、轻盈**。

- 白色作为主要阅读背景，紫色用于行动与链接。
- 暖桃色区分支持或参与区域；浅紫用于次级层次。
- 大标题建立品牌辨识，正文保持克制，留白形成阅读节奏。
- 粉、蓝、桃色光晕局限于 Hero 或装饰区，不能影响文字阅读。
- 真实品牌 Logo 保留原始比例与颜色；不以随机图形代替伙伴标识。
- 数字、合作关系、申请条件均应有来源；示例数据必须标明“示例”。

建议页面顺序：导航 → Hero → 生态参与者 → 建设与支持 → 公开进展 → 加入建设 → 页脚。

## 4. 字体与文字层级

官网声明字体为 **Avenir Next / PingFang SC**。当前 Figma 工具无法加载 Avenir Next，不能把替代字体视为与原稿完全一致。已有组件保留原字体；任何新组件的字体替代需明确记录。中文规范说明可使用 Noto Sans SC。

| 层级 | 字号 / 行高 | 字重 | 依据与用途 |
| --- | --- | --- | --- |
| 官网 Hero | 70 / 96 | Heavy / 900 | 官网 Ecosystem 实测，大标题 |
| 区块标题 | 40 / 54 | Bold / 700 | 官网 Ecosystem 实测 |
| Hero 副标题 | 26 / 36 | Medium / 500 | 官网 Ecosystem 实测 |
| 区块说明 | 20 / 28 | Regular / 400 | 官网 Ecosystem 实测 |
| 卡片标题 | 20 / 28 | Semibold / 600 | 官网社区卡实测，存在 PingFang SC 声明 |
| 操作文案 | 16 / 24 | Medium / 500 | 字号来自官网；24 行高为组件建议 |
| 卡片正文 | 14 / 20 | Regular–Medium | 官网社区卡实测 |
| 说明与来源 | 12 / 18 | Regular / 400 | 新增建议 |

新页面建议：中文 Hero 56 / 72；平板 44 / 58；手机 36 / 48。它们是响应式扩展，不能标成官网原始值。原稿中部分行高为 AUTO；浏览器行高与原稿 AUTO 分开记录。

文案原则：一个标题只表达一个重点。说明优先换行，不通过缩小字号塞入卡片。金额、时间、来源保持完整；长伙伴名称允许两行。

## 5. 布局、尺寸与间距

| 项目 | 官网 / 原稿依据 | 新设计使用方式 |
| --- | --- | --- |
| 桌面参考画板 | 原稿 1920px | 新稿用 1440px 为主，保留 1920 对照 |
| 内容容器 | 官网 1200px 容器，部分含左右 24px 内边距；原稿 1200px 内容 | 明确外框和可用内容宽，不混用 |
| 导航 | 官网 100px，旧稿 102px | 新稿采用官网 100px |
| 标准按钮 | 官网 50px 高、8px 圆角 | 产品/区块操作使用 |
| Hero 按钮 | 官网 Ecosystem 60px 高 | Hero 大操作使用 |
| 社区卡 | 官网 220 × 200、16px 圆角 | 作为社区入口密度参考 |
| 旧功能卡 | 原稿 380 × 251、16px 圆角 | 标题、说明的结构参考；内容增多时高度自适应 |
| 旧代币卡 | 原稿 1200px 宽、10px 圆角、40px 内边距 | 仅用于资产说明场景 |
| 栅格间距 | 旧稿 30px | 原稿保留；新页面建议 24 / 32px |

间距建议：4、8、12、16、20、24、32、40、48、64、80、100。图标与文案 8px；标题到说明 12–16px；卡片内边距 24–32px；区块之间 80–100px。保留官网特殊值作为专用尺寸，不强行四舍五入。

圆角：标签 4、按钮 8、资料卡 12（建议）、功能/伙伴卡 16。避免所有元素使用同一种大圆角。

建议断点：桌面 ≥1200；平板 768–1199；手机 <768。手机左右安全边距 20–24px；双栏与三栏改为单栏。伙伴展示允许手动横向滑动；自动滚动需可暂停，并响应“减少动态效果”。

## 6. 组件清单与设计要求

组件名建议采用 `JUST/Ecosystem/组件名`，默认 Light 模式。使用 Auto Layout；颜色、间距、圆角绑定统一变量。通用按钮先完成，再组装卡片。

| 组件 | 属性 / 状态 | 内容与使用规则 |
| --- | --- | --- |
| Button 按钮 | Primary / Secondary；50 / 60；Default / Hover / Pressed / Focus / Loading / Disabled | 24 个组合；文字可编辑。次按钮默认深色文字与深色描边，跟随官网。Loading 保留尺寸 |
| NavigationItem 导航项 | Default / Hover / Active / Focus | 选中同时用文字和下划线；点击区不小于 44px |
| SectionHeader 区块标题 | Left / Center；可隐藏英文小标题 | 标题、说明分别可编辑；不压缩文字高度 |
| PartnerCard 伙伴卡 | Default / Hover / Focus | 真 Logo、名称、能力说明、外链标识。Logo 可替换，Hover 不改变布局 |
| SupportItem 支持条目 | Default / Hover / Focus | 编号、支持方向、简短说明、可选跳转；用于开发、社区与长期发展方向 |
| ProgressCard 公开进展卡 | Default / Hover / Focus | 记录类型、标题、说明、来源、日期、查看入口。长标题可换行 |
| ParticipationCard 参与路径卡 | Default / Hover / Focus | 对象、行动标题、说明、行动链接；三条路径权重相近 |
| TextLink 文字链接 | External / Anchor；Default / Hover / Focus | 外链 ↗；页内 ↓；Hover 加下划线 |
| Badge 内容标签 | Neutral / Accent | 仅表达类别，不能充当按钮；当前生态页不需要沿用 Nova/Classica |
| ProductEntry / FeatureCard / TokenCard | 复用候选 | 已有 6 组组件包含这些类型；只在场景需要时使用，不将首页产品模块搬进 Ecosystem |

本次核对发现已有组件还引用外部变量；本文件本地变量列表为空。不能把“没有本地变量”说成“没有变量绑定”。新建的基础变量应可在本文件直接维护，旧组件是否迁移需单独评估。

优先制作：Button、TextLink、NavigationItem、SectionHeader、PartnerCard、SupportItem、ProgressCard、ParticipationCard。品牌 Logo 复用原稿矢量或官方资产；不重画成相似标识。

## 7. 状态与交互规范

- Default：看得出是否可操作；整卡跳转与局部按钮不要产生冲突。
- Hover：加深主色或改变边框；建议 150–200ms，尺寸不跳动。
- Pressed：比 Hover 更深；建议 100ms。
- Focus：2px 品牌紫外环 + 2px 间隔；在白色、暖色底上都要明显。
- Disabled：使用独立灰紫背景和文字，不能只降低整个组件透明度。
- Loading：保留按钮宽度、给出“处理中”，避免重复提交；不伪造成功。
- 数据区：区分加载、无数据、失败、更新延迟；缺失显示“—”，不是 0。
- 菜单：支持点击、键盘和 Escape；关闭后归还焦点。手机不依赖 Hover。
- 外链：图标提示离开当前站点；页内锚点考虑固定导航遮挡。

官网收益率和锁仓量会变化，不写入固定设计规范。组件演示使用“示例”或“—”。

## 9. 页面装配方式

1. Hero：英文小标题 + 中文主标题 + 简短说明 + 一主一次操作；右侧为三类参与者的关系视觉。
2. 伙伴：PartnerCard；展示能力与入口，避免把伙伴墙做成产品对比表。
3. 支持：左侧 SectionHeader + CTA，右侧三个 SupportItem。
4. 公开进展：两个 ProgressCard，保留来源与适用范围说明。
5. 参与：三个 ParticipationCard，对应合作、支持、社区声音。

三条路径的目标地址须在完整页面设计时核对。当前资料中的公开进展入口来自 JustLend DAO 官方渠道，不应直接声称所有计划覆盖整个 JUST 生态。

## 10. 设计交付验收

- 在 Assets 面板可找到真正的组件及变体，而非只有截图。
- Button 的 24 个状态组合命名一致；禁用和加载状态易于识别。
- 替换长标题、长伙伴名后不溢出；卡片高度可增长。
- 正文对比度目标 4.5:1，大字目标 3:1；交互目标建议至少 44 × 44px。
- 颜色、间距和圆角能通过变量集中修改；变量别名可以解析。
- 每类组件有用途、状态、内容属性与来源说明。
- 手机版本不是桌面稿缩小；保留完整来源和行动入口。
- 清晰标注官网实测、原稿依据、设计建议、字体差异。
