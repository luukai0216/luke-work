## 三、异常状态清单

> Footer 为纯静态导航结构，无异步数据加载，异常场景较少。


| 状态类型         | 触发场景                          | 处理方式                                     | 设计动作                           |
| ------------ | ----------------------------- | ---------------------------------------- | ------------------------------ |
| 链接失效 / 404   | MCP Server Docs URL 暂未上线或后续变更 | 由开发控制链接是否显示                              | ⚠️ 待确认：MCP 链接不可用时，是隐藏入口还是置灰禁用？ |
| 邮件客户端未配置     | App 端点击 "Support" 时设备无邮件应用    | 浏览器 / 系统行为，非产品层处理                        | 不需要设计异常态                       |
| 响应式折叠        | 官网移动端 Footer 导航列过多            | ⚠️ 待确认：PRD 未明确移动端折叠方案（手风琴 / 直接堆叠 / 简化列数） | 需补充                            |
| Telegram下拉为空 | 下拉菜单内容来源未在 PRD 中说明            | ⚠️ 待确认：Telegram 下拉的链接内容由谁维护、当前结构是什么      | 待明确后设计                         |
