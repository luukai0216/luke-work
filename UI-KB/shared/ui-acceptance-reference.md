# UI 验收通用参考

> 最后更新：2026-04-02
> 适用范围：所有项目（各项目专属规则见 `projects/{项目}/skills/ui-acceptance.md`）

---

## 触发方式

```
/ui-acceptance
```

或直接描述：「帮我做一下这个页面的 UI 验收」

---

## 输入材料

| 材料 | 是否必须 | 说明 |
|------|----------|------|
| Figma 设计稿链接 | **必须** | 格式：`figma.com/design/:fileKey/...?node-id=:nodeId` |
| 实现页面截图 | 建议提供 | 本地 PNG 文件路径，用于视觉对比 |
| 测试环境 URL | 建议提供 | 用于提取精确 CSS 数值（hex 色值、px 间距等） |
| 响应式截图 | 可选 | 移动端 / 平板端截图 |
| 交互状态截图 | 可选 | hover / focus / disabled 等状态截图 |

> 同时提供截图 + URL 效果最佳：URL 提取精确值，截图做视觉对比，两者互补。

## 四个验收维度

### 布局和间距

| 检查项 | 容差 |
|--------|------|
| padding / margin / gap | ±2px |
| 组件尺寸（宽/高） | ±4px |
| 对齐方式 / flex / grid 结构 | 无容差 |
| overflow / z-index 层叠 | 无容差 |

### 颜色和字体

- 背景色 / 文字色 / 边框色：hex 精确匹配，无容差
- font-size / font-weight / line-height
- 阴影参数 / 渐变色值
- 透明度 / letter-spacing

### 响应式表现

| 断点 | 宽度 | 说明 |
|------|------|------|
| 移动端 | ≤ 375px | 布局折叠 |
| 平板端 | 768px | 过渡布局 |
| 桌面端 | ≥ 1280px | 主视图 |

- 触摸目标最小尺寸：**≥ 44×44px**

### 交互状态

- `:hover` — 颜色 / 背景 / transform 变化
- `:focus` / `:focus-visible` — 焦点环样式
- `:disabled` — 禁用样式（opacity / cursor）
- CSS `transition` — 时长和缓动函数

## 问题严重程度

| 级别 | 定义 | 处理时机 |
|------|------|----------|
| **P0** 严重偏差 | 功能性错误、完全偏离设计、严重影响用户操作 | 上线前阻塞 |
| **P1** 明显差异 | 视觉可察觉，影响品牌一致性 | 上线前修复 |
| **P2** 细节优化 | 细微偏差，不影响整体效果 | 迭代中修复 |

## 报告结构

### 总体结论

`Pass` / `Needs Work` / `Fail`

### 问题表格字段

| 字段 | 说明 |
|------|------|
| ID | 问题编号，如 `#001` |
| 差异位置 | 组件名 + 属性，如「主按钮 · 背景色」 |
| 设计稿值 | Figma 中的目标值 |
| 开发实现值 | 页面实际值 |
| 严重程度 | P0 / P1 / P2 |
| 修复建议 | CSS 属性写法，如 `background-color: #5B6AF7` |

### 报告输出路径

```
~/Desktop/ui-acceptance-report-YYYYMMDD-HHmm.html
```

单文件，无外部依赖，可直接分享给开发或设计。

## 常用问题

**Q：只想验收某个组件，不想全页验收？**
输入时补充 `验收范围: 只验收 [组件名]`。

**Q：没有测试环境 URL 怎么办？**
仅用截图也可完成验收，CSS 数值通过视觉估算，精度略低。

**Q：报告打开是空白？**
截图以 base64 内嵌，文件较大（1–3 MB），用 Chrome 或 Safari 打开。

**Q：弹窗有多个状态怎么处理？**
每个状态提供一张截图并标注状态名（空态 / 有结果 / 无结果），AI 逐状态对比。
