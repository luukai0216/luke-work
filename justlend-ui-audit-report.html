10 个 UI 设计问题

每条包含影响判断与可执行的改进方向。

01

首屏同时争夺注意力的元素过多

高官网

大标题、长说明、3D 主视觉、浮动代币、主 CTA 与四项关键数据集中在首屏，几乎都使用高亮对比。用户进入后难以在 3–5 秒内判断“先理解产品”还是“立即进入 App”。

建议：首屏只保留一个核心信息链：价值主张 → 一句解释 → 主 CTA。将指标卡下移半屏，3D 装饰降低亮度或减少浮动元素数量。
02

核心 CTA 文案不够动作化，且命名不统一

中官网

界面中同时可见 “Just Launch” 与 “Launch App” 的表达。前者带有品牌双关，但对首次访问者不如 “Open App / Start Lending” 直接；相同目的使用不同文案也会削弱确定感。

建议：统一为一个动词短语，例如 “Launch App”；如果希望强化任务意图，可用 “Supply & Borrow” 作为次级入口。
03

正文可读性弱于品牌氛围

中官网

深色渐变与发光装饰营造了 DeFi 科技感，但说明文字颜色偏灰、行宽偏长，容易被标题和动效吞没。对非母语用户而言，长句阅读成本更高。

建议：正文最大宽度控制在 560–640px，提升文字对比度，拆成两行以内的短句；装饰光晕不要经过正文区域。
04

四项指标被平铺为同一层级，缺少解释

中官网

TVL、Grants Power、Ecosystem Users、APY 在视觉上权重接近，但它们分别代表规模、治理资金、用户量和浮动收益，含义与时效完全不同。APY 又是最容易影响决策、最需要时间说明的数据。

建议：指标按“规模 / 社区 / 收益”分组；APY 增加资产名、更新时间与“浮动”标签；给术语配置 tooltip 或说明链接。
05

顶层导航按组织结构命名，不够贴近用户任务

低官网

Applications、Documentation、DAO、Community 更像平台信息架构；用户真正要完成的是赚取收益、借款、质押 TRX 或租赁 Energy。任务入口主要依靠首屏文案与 CTA 暗示。

建议：导航优先呈现 “Earn / Borrow / Stake / Energy”，将 Docs、DAO、Community 收入 Resources 下拉，减少首次选择成本。
06

SBM V1 / V2 与多层菜单造成版本认知负担

高App

顶部同时出现 SBM V1、SBM V2、Supply & Borrow、Markets、Liquidation 等入口。产品版本名与用户任务混排，新用户必须先理解内部版本关系，才能判断该进入哪个市场。

建议：导航只暴露用户任务；将 V1 / V2 作为市场选择器，并明确标注 “Legacy / Recommended”。默认引导至推荐版本，旧版入口降级到二级位置。
07

未连接钱包时，大面积 “--” 形成伪故障感

中App

账户状态、净 APY、净资产等模块在未连接状态下只显示占位符。它们占据高价值首屏，却没有解释为什么为空、连接后能看到什么，也没有就近的下一步。

建议：用专门空状态替代数据卡：简短说明 + 钱包插画/图标 + “Connect Wallet” 主按钮 + 支持钱包提示。连接后再切换为账户仪表盘。
08

市场表格列过多，横向扫描路径过长

中App

资产、Supply APY、Borrow APY、流动性、钱包余额、抵押开关与多个操作按钮被放进同一行。高频比较项与低频账户项混在一起，用户很难快速找出“我该存哪个资产”。

建议：默认只保留资产、核心 APY、可用流动性与一个主操作；余额、抵押与次级操作进入展开行。提供 “Supply / Borrow” 视图切换与排序。
09

抵押开关与普通设置控件外观过于相似

中App

“Enable as collateral” 会改变清算风险，却以常规 toggle 呈现，并与 Supply / Borrow 操作紧邻。视觉上缺少风险级别、状态后果和确认感，容易被当作低成本偏好设置。

建议：使用带资产名的明确动作按钮；开启前展示简短风险确认，开启后用状态徽标和健康度联动表达影响，避免仅靠颜色区分。
10

品牌绿色承担过多语义，状态层级不够清晰

低App / 官网

绿色同时用于品牌、主按钮、正收益、选中态和部分装饰。不同含义共享同一高亮色，会降低用户对“可点击”“收益正向”“操作成功”三类信号的区分。

建议：建立语义色规范：品牌绿用于关键 CTA，正收益用更克制的 success 色，选中态以边框/底色组合表达；危险与警告保留独立红、橙色。

建议改版顺序

先处理会影响产品理解与资产安全感的问题，再统一信息表达和视觉细节。
